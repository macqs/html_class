# LLM HTML 연수 관리 대시보드 — 코드베이스 분석 보고서

전체 코드베이스, 설계 문서, 사용자 흐름을 분석하여 현재 서비스의 구조·원리를 정리하고, 확장·개선·보완 요소를 도출한 보고서입니다.

---

## 1. 서비스 개요

### 1.1 목적
특수학교 교사 대상 **LLM 활용 HTML 코딩 연수**를 위한 **실시간 관리 대시보드**. 참가자(교사)가 HTML 코드를 작성하고, 강사가 실시간으로 진행 상황을 모니터링·지원합니다.

### 1.2 기술 스택
| 영역 | 기술 |
|------|------|
| Frontend | Next.js 16 (App Router), React 19, TypeScript |
| Editor | Monaco Editor (VS Code 엔진) |
| Styling | Tailwind CSS v4 |
| Backend | Next.js API Routes |
| Database | Supabase (PostgreSQL) |
| Realtime | Supabase Realtime (Broadcast + Postgres Changes) |
| AI | Google Gemini 2.0 Flash API |
| Deployment | Vercel |

### 1.3 사용자 흐름
```
[강사] 세션 생성 → 세션코드/QR 공유
                    ↓
[참가자] 세션코드 입력 → 닉네임/좌석 선택 → 코드 에디터 입장
                    ↓
[강사 대시보드] 좌석 배치도 실시간 모니터링, 공지/예제 배포, 도움 요청 관리
```

## 2. 핵심 기능 현황

### 2.1 참가자 측
- **Monaco Editor** 기반 HTML 편집 (메모장 UI 스킨)
- **실시간 미리보기** (iframe sandbox)
- **AI 코드 검증** (Gemini 2.0 Flash) — 30초 쿨다운
- **도움 요청** — 30초 쿨다운, 코드 스냅샷 포함
- **자동 저장** (5초 간격) + 수동 저장
- **QR 코드 공유** — 작성한 HTML을 별도 URL로 공유
- **예제 라이브러리** — 강사 배포 예제 + 로컬 저장 작품 (최대 6개)
- **프롬프트 가이드** — AI에 넣을 프롬프트 초급/고급 모드 제공
- **확장자 변경 도구** 다운로드 (.txt → .html)

### 2.2 강사 측
- **좌석 배치도** — 실시간 상태 색상 표시 (미접속/대기/진행중/도움필요)
- **코드 미리보기** — 참가자 클릭 시 코드 확인
- **전체 공지** 브로드캐스트
- **예제 일괄 배포** — 과목 필터/검색, 다중 선택, 커스텀 코드 직접 입력
- **우수작 공유** — 특정 참가자 코드를 전체에 공유
- **워드클라우드 모드** — 실시간 키워드 수집·시각화, 첫/마지막 작성자 확인
- **접속 안내 팝업** — QR코드 + 세션코드 + 와이파이 정보
- **세션 관리** — 생성/삭제/종료, 세션코드 자동 생성

### 2.3 공통
- **두 가지 모드** 전환: HTML 실습 ↔ 워드클라우드
- **Realtime 그룹 채널** — 좌석 행 기준 2행당 1그룹으로 분할

## 3. 아키텍처 분석

### 3.1 강점
- **단순하고 실용적인 구조**: App Router 기반 깔끔한 라우팅, 컴포넌트 분리 양호
- **Supabase 활용도 높음**: DB + Realtime + SSR 서버 클라이언트 분리 적용
- **교육 현장 특화 UX**: 메모장 스킨, 큰 터치 영역(44px), 가이드 오버레이, 쿨다운 설계
- **워드클라우드 기능**: HTML 실습과 별도로 수업 활동에 활용 가능
- **보안 문서화**: SECURITY_FIXES.md에 취약점과 해결 방안 정리

## 4. 보완이 필요한 사항 (버그·기술 부채)

### 4.1 [높음] 인증/권한 체계 부재
- 현재 **로그인이 닉네임 입력**만으로 이루어짐 — 별도 인증 없음
- **강사 페이지에 접근 제한이 없음** — URL만 알면 누구나 강사 대시보드 접근 가능
- `instructor_id`가 하드코딩된 기본값 `instructor-001` 사용
- **권장**: 최소한 Supabase Auth (비밀번호/매직링크) 또는 간단한 PIN 인증 도입

### 4.2 [높음] RLS (Row Level Security) 미적용 가능성
- 코드에서 `supabase` 클라이언트(anon key)로 직접 CRUD → RLS 정책이 없으면 모든 데이터 노출
- 설계 문서에 RLS 언급은 있으나 실제 마이그레이션 SQL에 RLS 정책 미포함

### 4.3 [중간] 자동 저장 최적화 부족
- 5초마다 `setInterval`로 무조건 저장 — 코드 변경이 없어도 저장 요청 발생
- `SECURITY_FIXES.md`에 디바운스 방식을 권장하나 미적용 상태
- 100명 × 5초 = 분당 1,200건 INSERT → DB 부하 우려

### 4.4 [중간] 강사 대시보드 파일 크기 (1,016줄)
- `instructor/[sessionId]/page.tsx`가 1,016줄로 단일 파일에 너무 많은 로직 집중
- 모달, 예제 피커, 접속 안내 팝업 등을 별도 컴포넌트로 분리 권장

### 4.5 [중간] 에러 처리 일부 alert() 의존
- `alert()`, `confirm()`, `prompt()` 등 네이티브 다이얼로그 사용 — 모바일/태블릿 UX 저하
- 토스트 알림 시스템으로 교체 권장

### 4.6 [낮음] 오프라인/네트워크 복원 처리 없음
- 네트워크 끊김 시 Realtime 구독 자동 복구가 있으나, UI 상태 동기화 로직 부재
- 자동 저장 실패 시 사용자에게 알리지 않음 (자동 저장은 에러를 무시)

### 4.7 [낮음] 접근성(a11y) 개선 여지
- 모달에 `aria-modal`, focus trap 미적용
- 키보드 네비게이션 지원 부족 (좌석 배치도 등)

## 5. 확장·발전 제안

### 5.1 기능 확장

#### A. 퀴즈/투표 모드 추가
- 현재 HTML 실습 + 워드클라우드 2가지 모드 → **OX 퀴즈, 객관식, 순서 맞추기** 등 추가
- 워드클라우드 인프라(질문→응답→실시간 집계)를 그대로 활용 가능
- 수업 중 간단한 이해도 확인에 유용

#### B. AI 코드 생성 통합
- 현재는 외부 AI 링크(ChatGPT, Claude, Gemini)로 안내만 제공
- **에디터 내에서 직접 프롬프트 입력 → AI가 코드 생성 → 에디터에 삽입** 워크플로우
- Gemini API가 이미 연동되어 있어 추가 비용 없이 구현 가능

#### C. 협업 기능
- **짝 코딩**: 두 참가자가 같은 코드를 동시 편집 (Realtime broadcast 활용)
- **피어 리뷰**: 참가자끼리 코드를 교차 검토하고 피드백
- 수업 시나리오에 따라 개인/협업 모드 전환

#### D. 학습 진도 추적
- 예제별 완료 체크, 단계별 미션 시스템
- 참가자 대시보드에서 본인의 진도 확인
- 강사 리포트에서 전체 진도 히트맵 제공

#### E. 작품 갤러리
- 세션 종료 후 참가자들의 최종 작품을 갤러리로 공개
- 좋아요/투표 기능으로 인기 작품 선정
- 포트폴리오로 활용 가능

### 5.2 기술 개선

#### A. 상태 관리 고도화
- 현재 각 페이지에서 `useState` + `useEffect`로 직접 관리
- **Zustand** 또는 **React Query**를 도입하여 서버 상태 캐싱·동기화 단순화
- 특히 강사 대시보드의 복잡한 상태 흐름에 효과적

#### B. API Rate Limiting
- `SECURITY_FIXES.md`에 제안된 인메모리 rate limiter 적용
- Vercel Edge Middleware로 IP 기반 제한 추가 가능

#### C. 테스트 자동화
- 현재 테스트 코드 없음
- `scripts/load-test.mjs`가 부하 테스트용으로 존재하나 단위/통합 테스트 부재
- Playwright E2E 테스트로 핵심 흐름(로그인→코드작성→저장→도움요청) 커버 권장

#### D. 모니터링·관찰성
- Vercel Analytics + Sentry 에러 트래킹 도입
- Realtime 채널 성능 모니터링 (`monitorChannelPerformance` 함수가 이미 존재하나 미활용)

#### E. PWA / 오프라인 지원
- Service Worker로 기본적인 오프라인 대응
- 코드 자동 저장 실패 시 IndexedDB에 임시 저장 후 복구

### 5.3 콘텐츠 확장

#### A. 교과 예제 확대
- 현재 국어(16개), 수학(16개) HTML 예제 보유
- **과학, 사회, 영어, 음악, 미술** 등 추가 교과 예제 필요
- 난이도별(기초/중급/고급) 체계적 분류 강화

#### B. 프롬프트 템플릿 고도화
- 현재 초급/고급 2가지 프롬프트만 제공
- **교과별, 장애유형별, 활동유형별** 세분화된 프롬프트 라이브러리
- 사용자가 자주 쓰는 프롬프트를 저장·공유하는 기능

#### C. 다국어 지원
- 현재 한국어 전용 → 다문화 학생이나 해외 연수 대비 영어/다국어 UI 옵션

|------|-----------|-----------------|
| **기능 완성도** | 높음 (핵심 기능 대부분 구현) | 퀴즈/갤러리 등 부가 기능 확장 |

| **코드 품질** | 중간 (큰 파일 존재, 테스트 부재) | 컴포넌트 분리 + 테스트 도입 |
